# ระบบพยากรณ์น้ำไหลเข้าอ่างเก็บน้ำเขื่อนสิริกิติ์ (7 วันล่วงหน้า)

## โครงสร้างไฟล์
```
app.py              - แอปหลัก Streamlit (5 แท็บ: พยากรณ์ / อัปโหลดข้อมูล / ประวัติ / กราฟสรุป / หลังบ้าน Baseflow)
baseflow.py         - ล็อกอินผู้ดูแล + นำค่าปรับ Baseflow ไปบวกกับผลโมเดล
data_io.py          - อ่าน/เขียนข้อมูล รองรับทั้ง local และ Google Drive
features.py         - สร้าง feature (lag, rolling, ฤดูกาล, สถานีน้ำท่า)
model.py            - เทรนและพยากรณ์ (HistGradientBoostingRegressor x7 horizon)
station_parser.py   - parser ไฟล์สถานีน้ำท่ารูปแบบ RID Water Year (.txt)
shp_reader.py       - pure-Python shapefile reader + point-in-polygon (ไม่ต้องใช้ geopandas)
rainfall.py         - clip ฝนพยากรณ์ด้วยขอบเขตพื้นที่รับน้ำ (ยังไม่ได้ต่อเข้า app.py — ดูหัวข้อ "สิ่งที่ยังไม่เสร็จ")
requirements.txt    - ไลบรารีที่ต้องติดตั้ง
```

## รันทดสอบในเครื่องตัวเอง (โหมด local, ไม่ต้องมี Google Drive)
```bash
pip install -r requirements.txt
streamlit run app.py
```
โหมดนี้จะเก็บไฟล์ไว้ในโฟลเดอร์ `./data` แทน Google Drive — เหมาะสำหรับทดสอบว่าหน้าตา/การทำงานถูกต้องก่อน deploy จริง

## ตั้งค่า Google Drive สำหรับเก็บข้อมูลถาวร
1. เปิด https://console.cloud.google.com → สร้างโปรเจกต์ใหม่ (หรือใช้โปรเจกต์เดิม)
2. เปิดใช้งาน **Google Drive API** (เมนู APIs & Services → Enable APIs)
3. สร้าง **Service Account** (APIs & Services → Credentials → Create Credentials → Service Account)
4. สร้างคีย์แบบ **JSON** ให้ service account นั้น แล้วดาวน์โหลดไฟล์ .json มาเก็บไว้
5. เปิด Google Drive ของคุณ สร้างโฟลเดอร์ใหม่ 1 โฟลเดอร์สำหรับเก็บข้อมูลของแอปนี้
6. **แชร์โฟลเดอร์นั้นให้กับอีเมลของ service account** (อีเมลอยู่ในไฟล์ .json ช่อง `client_email`) สิทธิ์ระดับ "แก้ไขได้" (Editor)
7. คัดลอก **Folder ID** จาก URL ของโฟลเดอร์ (ส่วนท้ายของ URL หลัง `/folders/`)

## Deploy บน Streamlit Community Cloud
1. Push โค้ดทั้งหมดนี้ขึ้น GitHub repository
2. เข้า https://share.streamlit.io → New app → เลือก repo นี้ → ไฟล์หลัก `app.py`
3. ไปที่ **App settings → Secrets** ใส่ค่าตามรูปแบบนี้ (เอาข้อมูลจากไฟล์ .json ที่ดาวน์โหลดมาในขั้นตอนก่อนหน้า):
```toml
gdrive_folder_id = "ใส่ Folder ID ที่คัดลอกมา"

[gcp_service_account]
type = "service_account"
project_id = "..."
private_key_id = "..."
private_key = "-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
client_email = "...@....iam.gserviceaccount.com"
client_id = "..."
token_uri = "https://oauth2.googleapis.com/token"
```
4. กด Deploy — เมื่อ deploy เสร็จแอปจะได้ URL ถาวร (เช่น `yourapp.streamlit.app`) เปิดได้จากทุกเครื่อง

## การกรอกตารางข้อมูล
ตารางกรอกข้อมูล (อ่าง / สถานีน้ำท่า / ฝน / ค่าปรับ Baseflow) ใช้ `st.form` — แก้ไขในตารางได้ต่อเนื่องโดยหน้าไม่รีโหลดและยังไม่บันทึก จนกว่าจะกดปุ่ม "ยืนยันบันทึก"
ตารางสถานีน้ำท่ากรอกเฉพาะปริมาณน้ำ Q (ลบ.ม./วิ) ไม่มีช่องระดับน้ำแล้ว (ไฟล์เก่าที่เคยบันทึกระดับน้ำไว้ยังโหลดได้ แต่ไม่ถูกนำมาใช้)

## 🔧 หลังบ้าน: ปรับ Baseflow รายวัน (ผู้ดูแลเท่านั้น)
ผู้ดูแล (บัญชีใน `[admin_users]`) ที่ล็อกอินแล้วสามารถ **บวกเพิ่ม/ลด** น้ำไหลลงอ่างจากผลโมเดลได้รายวัน (7 วันข้างหน้า) ในแท็บ "🔧 หลังบ้าน (Baseflow)"

- กรอกเป็น **ลบ.ม./วินาที (cms)** ระบบแปลงเป็น ล้าน ลบ.ม./วัน ให้เอง (× 0.0864) แล้วบวกกับผลโมเดล ผลรวมต่อวันไม่ต่ำกว่า 0
- ค่าที่ปรับมีผลทันทีที่แท็บ "พยากรณ์" และ "กราฟสรุป" (รวมสมดุลน้ำและรายงานรูปภาพ) และมีข้อความแจ้งผู้ใช้ว่าเป็นค่าที่ปรับแล้ว พร้อมแสดงผลดิบจากโมเดลเทียบ
- ค่าปรับผูกกับ **วันที่จริง** (ไม่ใช่ "วันที่ 1-7") เมื่อมีข้อมูลอ่างวันใหม่เข้ามา วันที่ที่ซ้อนกันยังคงมีค่าปรับเดิม ส่วนวันใหม่เริ่มที่ 0
- `forecastlog_*.csv` ยังเก็บ **ผลดิบจากโมเดล** เสมอ (ไม่รวมค่าปรับ) เพื่อให้ประเมินความแม่นของโมเดลได้ตรงไปตรงมา
- ทุกครั้งที่บันทึกจะมี audit log แยกไฟล์ (`baseflowlog_*.csv`) ดูย้อนหลังได้ในหน้านั้นว่าใครปรับอะไรเมื่อไหร่
- ผู้ใช้ทั่วไป (`[users]`) เห็นแท็บนี้แต่แก้ไม่ได้ ถ้ายังไม่ตั้งบัญชี หน้านี้จะถูกล็อกไว้

### บัญชีผู้ใช้และสิทธิ์ (App settings → Secrets)
ต้องเข้าสู่ระบบก่อนจึงจะ **รันโมเดล** ได้ (แท็บ "พยากรณ์" รวมปุ่มเทรน/รันพยากรณ์ และแท็บ "กราฟสรุป") — ช่องล็อกอินอยู่บนสุดของหน้า
| บทบาท | หมวดใน Secrets | ทำอะไรได้ |
|---|---|---|
| ผู้ใช้ | `[users]` | รันโมเดล, ดูกราฟสรุป/รายงาน |
| ผู้ดูแล | `[admin_users]` | ทุกอย่างของผู้ใช้ + ปรับ Baseflow ในแท็บหลังบ้าน |

```toml
[users]
nong = "sha256:<ค่า hash>"

[admin_users]
somchai = "sha256:<ค่า hash>"
```
- ใส่รหัสผ่านตรงๆ ก็ได้ แต่แนะนำเก็บเป็น hash สร้างได้ด้วย
```bash
python -c "import hashlib; print('sha256:' + hashlib.sha256('รหัสผ่านของคุณ'.encode()).hexdigest())"
```
- ชื่อซ้ำกันทั้งสองหมวด → ถือเป็นผู้ดูแล
- แท็บ "อัปโหลดข้อมูลใหม่" และ "ประวัติ" ยังเปิดโดยไม่ต้องล็อกอิน (ตามที่ตกลงว่าบังคับล็อกอินเฉพาะการรันโมเดล) — ถ้าต้องการให้ล็อกอินก่อนกรอก/อัปโหลดข้อมูลด้วย แจ้งได้
- ถ้ายังไม่ตั้งบัญชีเลย ระบบจะ **ไม่อนุญาตให้รันโมเดล** (ไม่มีโหมดเปิดโล่ง) ทดสอบในเครื่อง: สร้าง `.streamlit/secrets.toml` ใส่หัวข้อแบบเดียวกัน

> หมายเหตุด้านความปลอดภัย: ระบบล็อกอินนี้เป็นแบบง่าย (บัญชีใน Secrets + จำกัดการลองรหัสต่อ session) เหมาะกับใช้ภายในทีม
> ไม่ใช่ระบบยืนยันตัวตนระดับองค์กร ถ้าต้องการเข้มกว่านี้ควรใช้ `st.login()` (OIDC) หรือจำกัดผู้เข้าถึงแอปที่ระดับ Streamlit Cloud

## สรุปผลโมเดลปัจจุบัน (ทดสอบกับข้อมูลปี 2024 - มี.ค. 2026 ที่ไม่เคยเทรน)
| วันล่วงหน้า | MAE | RMSE | R² |
|---|---|---|---|
| 1 | 4.78 | 12.31 | 0.879 |
| 2 | 5.44 | 14.42 | 0.834 |
| 3 | 7.60 | 19.58 | 0.694 |
| 4 | 9.40 | 22.81 | 0.584 |
| 5 | 10.06 | 24.38 | 0.525 |
| 6 | 10.53 | 25.89 | 0.465 |
| 7 | 11.04 | 26.67 | 0.432 |

โมเดลชนะ naive baseline (ใช้ค่าเมื่อวานซ้ำ) ทุก horizon โดยเฉพาะวันที่ 1-2 ที่ดีขึ้นราว 45% หลังเพิ่มตัวแปรสถานีน้ำท่า (N.1, N.13A, N.64)

## ⚠️ ข้อจำกัดที่ทราบอยู่แล้ว (สำคัญ อ่านก่อนใช้งานจริง)
1. **พยากรณ์ต่ำกว่าจริงในช่วงน้ำมาก/น้ำท่วมฉับพลัน** โดยเฉพาะวันที่ 4-7 — เพราะยังไม่มีข้อมูลฝนพยากรณ์ล่วงหน้าเป็น feature จริง (มีแค่โมดูล `rainfall.py` เตรียมไว้ ยังไม่ได้ต่อเข้า pipeline การเทรน เนื่องจากยังไม่มีข้อมูลฝนย้อนหลัง 20 ปีมาเทรน)
2. **overfitting ในโมเดล horizon 4-7** (R² train ~0.93 แต่ test เหลือ 0.43-0.58) —ยังไม่ได้ปรับ regularization
3. **LSTM ยังไม่ได้ทำ** — ทดลองแล้วว่า HistGradientBoostingRegressor beat naive baseline ได้ดี จึงใช้เป็น baseline หลักก่อน

## สิ่งที่ยังไม่เสร็จ / ทำต่อได้
- ต่อโมดูล `rainfall.py` เข้ากับ `features.py`/`model.py` เป็น feature จริง (ต้องหาข้อมูลฝนย้อนหลังมาเทรนก่อน เช่น Open-Meteo Historical API)
- Quantile regression หรือ weighted loss เพื่อลดปัญหาพยากรณ์ต่ำกว่าจริงช่วงน้ำมาก
- ปรับ regularization ของโมเดล horizon 4-7 ลด overfitting
- หน้าอัปโหลดไฟล์ฝนพยากรณ์ + shapefile ในตัวแอป (ตอนนี้ทำได้แค่ผ่านโค้ดโดยตรง ยังไม่มี UI)
- ระบบแจ้งเตือนอัตโนมัติ (เช่น LINE Notify) เมื่อพยากรณ์เกินเกณฑ์ที่กำหนด

## ฟีเจอร์เพิ่มเติม: แผนระบายรายวันและ Rule Curve
- แท็บ **หลังบ้าน (Baseflow)** มีตาราง **แผนการระบายรายวัน** สำหรับ 7 วันข้างหน้า ใส่ค่าแต่ละวันไม่เท่ากันได้ หน่วยล้าน ลบ.ม./วัน
- หน้า **กราฟสรุป** ใช้แผนระบายที่บันทึกไว้รายวันคำนวณแนวโน้มปริมาณน้ำคงเหลือด้วยสมดุลน้ำอย่างง่าย: น้ำคงเหลือวันก่อน + น้ำไหลเข้าคาดการณ์ - แผนระบาย
- หากไม่มีแผนระบายของวันใด ระบบใช้ค่าเฉลี่ยการระบายจริง 7 วันล่าสุดเป็นค่าเริ่มต้น
- แท็บ **อัปโหลดข้อมูลใหม่** มีหัวข้อ **อัปโหลด Rule Curve / เกณฑ์ระดับน้ำอ่าง** รองรับ .xlsx และ .csv โดยต้องมีคอลัมน์วันที่ และอย่างน้อยหนึ่งคอลัมน์จาก `upper_storage`, `lower_storage` (ล้าน ลบ.ม.) หรือ `upper_level`, `lower_level` (ม.รทก.)
- ชื่อคอลัมน์ภาษาไทยที่รองรับ: `วันที่`, `Upper Rule Curve`, `Lower Rule Curve`, `ระดับเก็บกักบน`, `ระดับเก็บกักล่าง`, `ระดับน้ำบน`, `ระดับน้ำล่าง`.
- Rule Curve ที่เป็นปริมาตรน้ำจะแสดงในกราฟปริมาณน้ำในอ่าง ส่วน Rule Curve ที่เป็นระดับน้ำจะแสดงแยกในกราฟระดับน้ำจริง เพื่อไม่ปะปนหน่วย
- **ข้อจำกัดสำคัญ:** ระบบยังไม่แปลงปริมาณน้ำคาดการณ์เป็นระดับน้ำคาดการณ์ เพราะต้องมีตารางความสัมพันธ์ระดับน้ำ-ปริมาตรน้ำที่เชื่อถือได้ก่อน และผลปริมาณน้ำคงเหลือเป็นการจำลองตามแผนระบาย ไม่ใช่ผลจากโมเดล ML โดยตรง


## รุ่นไม่ใช้ระบบ Admin

หน้าเว็บไม่ต้องล็อกอินและไม่มีแท็บ Admin/หลังบ้านแล้ว แต่ข้อมูลการปรับ Baseflow ที่เคยบันทึกไว้ยังถูกนำไปใช้คำนวณหากมีอยู่ในพื้นที่เก็บข้อมูลเดิม กรุณาตรวจสอบข้อมูลก่อนใช้งานจริง

แท็บอัปโหลดข้อมูลใหม่รองรับ Rule Curve แบบ CSV/XLSX ที่มีหัวตาราง `วันที่`, `date`, `ความจุที่ (รนส.)`, `ความจุที่ (รนก.)`, `Upper Rule Curve`, `Lower Rule Curve` (หน่วยล้าน ลบ.ม.) หากมีทั้งสองคอลัมน์วันที่ ระบบใช้ `date` ก่อน
